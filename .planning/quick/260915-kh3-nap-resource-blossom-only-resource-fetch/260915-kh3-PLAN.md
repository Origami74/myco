# NAP-RESOURCE (blossom only)

`resource.info`, `resource.bytes`, `resource.bytesMany`, `resource.cancel`
per the registry draft (PR #13, pinned in `reference/naps/drafts/NAP-RESOURCE.md`).
Only the `blossom:` scheme is enabled; `https:`, `data:` (shim-local anyway),
`htree:`, `nostr:` report `unsupported-scheme`. Every fetch reads the local
Blossom store first; a miss is fetched from Circle peers' Blossom over the
mesh and then the public servers (unless offline-only), verified, and **stored
locally** before delivery.

## Tasks

1. **Runtime.** `NapContext.blobs` (the `BlobStore` seam) and a `BlobFetcher`
   seam (`fetch(sha256) -> Option<bytes>`); `nap/resource.rs` with the four
   actions, `blossom:` URL parsing, byte-sniffed `mime` (raw SVG refused as
   `blocked-by-policy`), 10 MiB cap, 100-URL bulk cap, `.error` envelopes with
   the spec's codes; bytes travel as base64 in `blob` (JSON wire). Tests.
2. **Shell.** `shell.html` turns a base64 `blob` in `resource.bytes.result` /
   `bytesMany.result.items` into a `Blob` typed by `mime` before it reaches
   the napplet, so the vendored shim's `result.blob` is what it expects.
3. **Core.** `BlossomFetcher`: reachable Circle members' mesh Blossom, then
   the public servers via `IpPeerSource`, bounded; wired into `NappletHost`.
4. **Docs.** design doc S2 line, CHANGELOG. Grant wording exists.
