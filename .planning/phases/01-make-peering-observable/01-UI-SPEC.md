# Phase 1 — UI Design Contract

> Visual and interaction contract for the Dev-tab peer diagnostics rebuild (D-01..D-19 in
> `01-CONTEXT.md`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** DIAG-01, DIAG-03, DIAG-04, DIAG-05, DIAG-06, DIAG-07. No reason codes
(DIAG-02 — Phase 2). No new top-level destination (D-01: Dev tab only). No per-peer detail
screen (D-05: expand in place).

## Design System

| Property | Value |
|----------|-------|
| Tool | none — this is an Android Jetpack Compose (Kotlin) module, not React/Next/Vite. The shadcn registry model does not apply; the `shadcn_gate` was checked and skipped for this reason (no `components.json`, no `package.json` at the Android module boundary, tech stack confirmed via `android/app/src/main/java/app/myco/ui/`). |
| Preset | not applicable |
| Component library | Material3 (`androidx.compose.material3`) wrapped by the project's own `MycoTheme` (`android/app/src/main/java/app/myco/ui/theme/Theme.kt`). No Material You / dynamic color (fixed brand palette, targets API 29+). Local composable library already exists and MUST be reused, not rewritten, per D-03: `SectionCard`, `ScreenHeader`, `GroupLabel`, `StatusDot`, `KeyVal` (`MycoApp.kt`) and `DevCard`, `KeyValDot`, `PeerRow`, `AwareLinkRow`, `ApNodeRow`, `AdvertRow`, `EmptyLine`, `short()` (`DevScreen.kt`). |
| Icon library | Material Icons (`androidx.compose.material.icons.Icons.Filled` / `.AutoMirrored`) — used elsewhere in the app (`SettingsScreen.kt`). **Not used inside the Dev tab today.** The Dev tab's existing convention is glyph + color, not vector icons: `StatusDot` (a colored circle) plus `●`/`○` text glyphs (see `PeerRow`, `AwareLinkRow`, `ApNodeRow`). New Phase 1 composables (radio self-check, expanded peer detail, attempt-log rows, pair-request rows) MUST follow this existing glyph+color convention, not introduce Material Icons into this screen — mixing the two vocabularies inside one card grid would read as inconsistent. |
| Font | System default (no custom font family loaded for body text). `FontFamily.Monospace` is used throughout the Dev tab for addresses, npubs, hex values, byte counts and other exact/comparable numeric data (`KeyValDot`, `PeerRow`, `AdvertRow`, `SpeedtestCard`'s result line) — this convention carries forward unchanged: any new numeric/hex/npub value this phase adds (discovery latency in ms, drop counts, RSSI, attempt timestamps) renders in monospace. |

## Spacing Scale

Declared values (must be multiples of 4), for **new** composables added by this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/dot-to-label gaps inside a row |
| sm | 8px | Compact spacing inside expanded peer-row detail (role/latency/drop lines) |
| md | 16px | Row horizontal padding — matches existing `KeyVal`/`KeyValDot`/`PeerRow` convention |
| lg | 24px | Reserved; no lg-scale gap is expected within a single Dev-tab card this phase |

**Exceptions — pre-existing, reused-not-rewritten tokens (D-03) that new code sits alongside and must visually match, even though they are not multiples of 4/8:**

| Value | Where it's already used | Rule for Phase 1 |
|-------|--------------------------|-------------------|
| 6px | Vertical row padding (`KeyVal`, `KeyValDot`, `PeerRow`, `AwareLinkRow`), dot-to-text gap in `PeersOverviewCard` | Reuse verbatim inside rows that share a card with existing rows (e.g. a peer row sitting in the same list as legacy-styled rows). Do not introduce 6px in a card that has no legacy neighbor — use `sm` (8px) instead. |
| 9px | `StatusDot` default diameter | This is an icon-size token, not a spacing token. Keep it; do not redefine peer-state dot size for the five-state vocabulary (D-10) — reuse `StatusDot(color)` as-is so dot sizing stays uniform across the whole app. |
| 14px | `Arrangement.spacedBy(14.dp)` between top-level Dev-tab cards, and inside the `SelectionContainer` card column | This is the established card-to-card rhythm for this screen. New top-level cards (radio self-check, peer list, pending pairings, identity) MUST use this same 14px gap so the rebuilt screen reads as one system, not as legacy cards plus a bolted-on new section. |
| 18px | `SectionCard` corner radius | Visual radius token, unrelated to spacing; unchanged. |
| 20px | Screen-level `Column` padding in `DevScreen` | Unchanged — the screen's outer margin. |

**Net rule:** inside a single new card, use 4/8/16 (xs/sm/md). Between cards, and inside any row that is visually a peer of an existing legacy row, match the legacy 6px/14px rhythm so the screen doesn't look like two different systems stitched together.

## Typography

The project overrides only `displaySmall` in `MycoTheme`; every other style used in the Dev
tab is Material3's default `Typography()` value. Phase 1 reuses this system rather than
introducing new type styles.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (screen title, "Dev") | 34sp | ExtraBold (800) — pre-existing override, unchanged this phase | 40sp |
| Heading (card/section title, e.g. "PEERS (3)") | 14sp (`titleSmall`) | Bold (700) — pre-existing (`DevCard`'s explicit `FontWeight.Bold`), unchanged this phase | 20sp |
| Body (row labels, values, radio self-check facts) | 14sp (`bodyMedium`) / 12sp (`bodySmall`) | **Regular (400)** — new elements' default | 20sp / 16sp (M3 default, unchanged) |
| Label (status values, legend captions, e.g. "aware = Wi-Fi Aware…") | 12sp (`labelMedium`) / 11sp (`labelSmall`) | **SemiBold (600)** — new elements' emphasis weight, matching `KeyValDot`'s existing `FontWeight.SemiBold` on "ok" values | 16sp (M3 default, unchanged) |

**Weight contract for new Phase 1 elements specifically:** declare exactly **two** weights —
**Regular (400)** for plain facts/values and **SemiBold (600)** for emphasized/positive status
values (mirroring `KeyValDot`'s existing pattern: label in Regular `onSurfaceVariant`, "ok"
value in SemiBold + status color). Do not introduce a third weight in new composables. Bold
(700) on card headers and ExtraBold (800) on the screen title are pre-existing, out-of-scope
inherited styles (D-03: reused, not rewritten) — leave them as-is, do not extend Bold/ExtraBold
usage into new row-level content.

## Color

This screen uses two color systems side by side — brand chrome and mesh-state semantics. Both
are pre-existing in `Theme.kt`; **no new color constants are introduced this phase** (D-10 is
explicit: the five peer states reuse existing colors so `ThemeTest.kt` stays green).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `MaterialTheme.colorScheme.background` / `.surface` (white `#FFFFFF` light, black AMOLED dark) | Screen background |
| Secondary (30%) | `MaterialTheme.colorScheme.surfaceVariant` (`#F4F5F7` light / black AMOLED) | `SectionCard` fill for every card: radio self-check, peer list, pending pairings, identity, speedtest |
| Accent (10%) — brand | `MaterialTheme.colorScheme.primary` = Emerald `#059669` (light) / `#34D399` AMOLED | Reserved for: card/section title text (`DevCard`'s title, e.g. "PEERS (3)"), and interactive button labels (the existing Speedtest "Run"/"Retry" `TextButton`, unchanged). **Not** used to indicate peer/radio state — that is a separate palette below. |
| Destructive / error | `MaterialTheme.colorScheme.error` = `#DC2626` (light) / `#FF6B6B` AMOLED | Reserved for genuine failures only: an existing Speedtest run that errored (`SpeedtestCard`'s `st.error` line, kept). **Explicitly not used** for the zero-peers empty state or for a corrupted/missing attempt log (D-13) — those degrade quietly to neutral copy, never to red, because they are not failures the user needs to act on. |

Accent reserved for: card/section title text, interactive button labels. Never used for peer
connection state, radio enabled/scanning state, or attempt-log outcomes — those use the
mesh-state palette below.

**Mesh-state palette (semantic, not brand — pre-existing, reused verbatim):**

| Constant | Value | Meaning in this phase |
|----------|-------|------------------------|
| `StatusConnected` | `#22C55E` | Peer state: `connected`. Also: radio self-check "enabled"/"scanning" = true (`KeyValDot`'s `ok=true` convention). |
| `StatusReachable` | `#14B8A6` | Peer state: `reachable-via-relay`. |
| `StatusThin` | `#F59E0B` (amber) | Peer state: `paired-offline` — paired, not currently connected, reads as "waiting" rather than "gone". |
| `StatusAlone` | `#EF4444` (red) | Peer state: `unreachable` — the true fault state, distinct from `error` above (this is peer-specific, not app-level). |
| `onSurfaceVariant` (Slate `#64748B`) | neutral | Peer state: `seen-unidentified` — no identity yet, so no status color; a neutral dot, matching the existing "○ seen" convention in `PeerRow`. Also: radio self-check "enabled"/"scanning" = false. |

This is a five-value superset of a strict accent/destructive binary because D-10 requires five
peer states; document it explicitly here so the checker's Color dimension evaluates the whole
palette rather than flagging the extra rows as undeclared color.

## Focal Point & Visual Hierarchy

Primary focal point: the **radio self-check card** — it is the diagnostic entry point that answers
D-07's "is it me or is it them" question, so it renders first and is never scrolled past to reach
the peer list.

Visual order, top to bottom:

1. Radio self-check card (focal point — BLE enabled/scanning/advertising, Wi-Fi Aware available)
2. Peer list card (the screen's bulk content; scrollable, D-11 ordering)
3. Pending pair requests card
4. Identity card
5. Speedtest card (demoted below all peering content, D-04)

Interaction depth is flat: peer rows expand **in place** (D-05) — there is no per-peer detail
screen and no navigation away from the Dev tab. Emphasis within a card comes from the SemiBold
(600) status value and its state-colored dot, never from size jumps: all row-level content stays
at 14sp/12sp so hierarchy reads through position and color, not scale.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None. Phase 1 has no primary call-to-action — this is a read-only diagnostics screen (D-15: no export). The only interaction is tap-to-expand a peer row (D-05), which is a disclosure, not a CTA.
