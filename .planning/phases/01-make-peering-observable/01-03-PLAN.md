<objective>
Record, per peer, the BLE role this device chose, how long discovery took, how the attempt
resolved, and how many sends to that peer failed — then keep a bounded, crash-surviving history
of those attempts so a race that resolved thirty seconds ago still leaves evidence.

Purpose: the roadmap's first sequencing constraint says Phase 2 must not be spent guessing. The
tiebreaker in `ble/mod.rs` looks deterministic in source and is unit-tested for the convention,
but nothing records whether both sides actually agree at runtime — that decision exists only as
a debug trace. This plan turns those traces into per-peer structured state, which is the
artefact that confirms or kills the tiebreaker-race hypothesis before Phase 2 acts on it.

Output: a generic bounded attempt log inside the fips BLE transport, recording at every existing
outcome site; a corruption-tolerant JSONL store in `myco-core`; and the role, discovery latency,
drop count and attempt history joined onto every peer row.
</objective>

## Planner assumptions and breadcrumbs

- **Attempt boundary (Claude's Discretion, CONTEXT.md; RESEARCH Open Question 2).** Pinned to one
  entry per discovery-to-resolution cycle, resolution being exactly one outcome enum value. The
  finer per-trace granularity was rejected because it burns the 20-entry cap on fragments of a
  single attempt.
- **Record shape and cap (Claude's Discretion).** Pinned to `{at_ms, ble_addr, node_addr_hex,
  role, discovery_ms, outcome}` and `MAX_ATTEMPTS_PER_PEER = 20`; eviction threshold 24 hours
  since a peer's newest attempt.
- **Transport of the log to the UI (Claude's Discretion).** Pinned to riding the same `state()`
  payload as the peer rows — 20 small records per peer at demo-room peer counts is a few
  kilobytes, and it removes the expand-time fetch the UI-SPEC left open at E3.
- **On-disk encoding (Claude's Discretion, subject to D-13).** Pinned to newline-delimited JSON.
  Whole-document JSON is what makes one bad byte destroy an entire file, which is the known
  defect D-13 forbids repeating.
- **Where the log lives (RESEARCH Open Question 1).** A process-global bounded log in the fips BLE
  module, reached through a free accessor in the same shape as the existing global BLE bridge in
  `android_io.rs`. Threading a new argument into `accept_loop` and `scan_probe_loop` was rejected:
  both already carry a too-many-arguments allowance, and a wider signature is a larger, harder
  upstream diff than a module-local singleton. Retention and persistence stay entirely in
  `myco-core` — fips holds only the live in-memory ring.
- **fips genericity.** `attempts.rs` names no Myco type, no app concept and no Android API. Any
  fips embedder benefits from knowing which role it picked, how long discovery took, and how many
  sends failed; the diff is one new module plus record calls beside existing `debug!` traces, and
  stands alone as an upstream PR.
- **Edge coverage.** This plan resolves the DIAG-01 concurrency edge as a backstop. Zero dropped.

Give the attempt log a bounded, crash-surviving home on disk whose read path cannot lose a whole
file to one bad byte, and whose write path cannot destroy a good file without preserving a copy.

Create `myco-core/src/attempt_store.rs` and declare it in `lib.rs`. Define `PersistedAttempt`
(`Serialize` + `Deserialize`, camelCase, fields mirroring the fips record: `at_ms`, `ble_addr`,
`node_addr_hex`, `role`, `discovery_ms`, `outcome`) and `AttemptStore` holding the data-dir path,
an in-memory map from address to a bounded `VecDeque<PersistedAttempt>`, a dirty flag and the
last-flush instant.

Read path — `AttemptStore::load(path)`: open `<data_dir>/ble-attempts.jsonl`; a missing file is
an empty history and not an error. Read it line by line through a buffered reader and
deserialize each line on its own, counting the lines that fail and keeping the ones that
succeed. Never treat the file as a single document — that is precisely the failure mode where
one corrupt byte costs the entire history, and it is what this store exists not to repeat. A
truncated final line costs one entry. If more than half the non-empty lines failed to parse,
copy the file to `<data_dir>/ble-attempts.jsonl.corrupt` before the store is ever allowed to
write, so a still-good file is preserved rather than replaced. Nothing in this path panics,
unwraps, or rewrites the source file.

Observe path — `AttemptStore::observe(&mut self, snapshot)`: fold new records in, deduplicating
on the address plus timestamp pair, truncating each address's ring from the front to 20, and
setting the dirty flag only when something actually changed. This runs inside `state()`, so it
must be allocation-and-compare only: no file I/O, no blocking.

Write path — `AttemptStore::flush(&self)`: serialize one record per line and write with the
atomic temporary-file-then-rename pattern copied verbatim from the existing Circle save. Before
serializing, drop every address whose newest attempt is older than 24 hours, so the file stays
bounded by peer count rather than by uptime. A flush is attempted at most once every 5 seconds
and only when dirty.

Wire it into `AppRuntime`: load once during construction, hold the store, call `observe` from
`state()` after the attempt snapshot is read, and spawn the flush on the tokio runtime when the
store is dirty and the flush interval has elapsed — never on the FFI thread. On construction
failure the store degrades to an empty in-memory history and records nothing into
`AppState.error`; a diagnostics file is not worth surfacing an app-level banner for.

Merge the loaded history with the live fips snapshot before it reaches `merge_peers`, so a
freshly launched app shows the attempts recorded before the last force-stop and the newest live
ones together, deduplicated and newest-first.

Unit tests: a round trip through save then load; a file with a truncated final line yielding the
earlier entries; a file whose lines are mostly garbage yielding no history and producing the
preserved copy while leaving the original bytes intact; a missing file yielding no history and
no preserved copy; the ring capping at 20; and eviction dropping an address whose newest entry
is older than the threshold while keeping a fresher one.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mesh peer to this device | A peer controls how often it probes this phone, and therefore how fast that peer's own ring churns |
| process to disk | The attempt log is a persisted record of which devices were near this phone and when |
| disk to process | A corrupted or attacker-modified log file is parsed at every launch |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering / denial of service | `AttemptStore::load` | high | mitigate | Line-delimited parsing with per-line failure isolation, no whole-document deserialize, no unwrap on the non-test path, and no rewrite of the source file on a read failure. A malformed file yields no history rather than a panic at startup. Gated by the negative source assertions and the mostly-garbage unit test. |
| T-03-02 | Tampering (data loss) | `AttemptStore::flush` over a corrupt file | high | mitigate | A file whose majority of lines failed to parse is copied to a `.corrupt` sibling before the store writes, so a still-good file is never silently replaced with a shorter one. |
| T-03-03 | Information disclosure | `<data_dir>/ble-attempts.jsonl` | medium | mitigate | Records carry only locally-generated values — timestamps, an outcome enum, a role enum, a duration, and addresses the device already stores in `circle.json` — never peer-supplied free text. Age-based eviction bounds how far back the proximity record reaches. The file lives in the app-private data dir with no export path (D-15). |
| T-03-04 | Denial of service (storage) | unbounded log growth | medium | mitigate | Per-address cap of 20 pruned on write plus 24-hour eviction, so size is bounded by peer count rather than uptime; no background job and no rotation logic. |
| T-03-05 | Denial of service (diagnostic integrity) | a peer flooding connect attempts to evict its own history | low | accept | The cap is per address, so a flood against one peer's ring cannot displace another peer's history — and a fast-churning full ring for one peer is itself the evidence Phase 2 needs. |
| T-03-06 | Denial of service (FFI thread) | `observe` running inside `state()` | medium | mitigate | `observe` performs no I/O; the flush is spawned on the tokio runtime and rate-limited to once every 5 seconds, so the FFI thread never waits on the disk. |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | Zero packages installed; the ring uses `std::collections::VecDeque` and the parse uses the already-pinned `serde_json`, per RESEARCH.md's Package Legitimacy Audit. |
