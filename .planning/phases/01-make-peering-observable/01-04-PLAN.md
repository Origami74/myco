<objective>
Rebuild the Dev tab around peering so the person holding the phone can answer, without a
debugger, whether the fault is local or remote, what every peer's true state is, and why a
particular connection failed.

Purpose: everything the previous three plans record is only worth recording if it is legible at
a demo, standing next to a second phone. D-07 puts the radio self-check first because zero peers
is the actual field complaint. D-05 keeps peer detail in place because comparing two phones side
by side must not cost you your place in the list.

Output: the Dev tab in its final column order, with a radio self-check card, expanding peer rows
carrying the failure forensics, pending pair requests, identity, and the speedtest demoted below
all peering content.
</objective>

## Planner assumptions and breadcrumbs

- **First-frame behaviour (Claude's Discretion, CONTEXT.md).** The screen receives the hoisted
  `AppState` from the shell as its initial value and then refreshes on its own cadence, so there
  is no pre-first-payload frame in practice. The UI-SPEC's four loading rows are preserved as
  backstops anyway, since nothing pins that transient frame with a test.
- **Row transition animation (Claude's Discretion).** None this phase. Expansion is an immediate
  disclosure; an animation would fight the one-second refresh and add nothing at a demo.
- **Collapsed summary composition (Claude's Discretion).** State glyph and dot, then the
  shortened npub with the Circle name when one exists, then the transport and the exact-seconds
  last-heard counter as the trailing monospace value — the existing two-line row anatomy with a
  tap target added, not a new row type.
- **D-06 is already satisfied** at `MainActivity.kt` where the developer-mode preference defaults
  to the debug-build flag. This plan verifies it rather than reimplementing it, and touches
  neither `MainActivity.kt` nor `MycoApp.kt`.
- **Edge coverage.** This plan carries all 48 UI-SPEC `## UI Considerations` items — 42 covered,
  6 backstop — plus the DIAG-05 ordering edge and both DIAG-07 edges. Zero unresolved, zero dropped.
